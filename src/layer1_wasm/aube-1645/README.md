# Reproduction — aubepkg/aube#1645

> The first Layer 1 recipe that compiles an upstream **application** to
> `wasm32-wasip1`: aube's own lockfile reader runs in the browser,
> against a fixture project written to an in-memory `/tmp`.
> Conforms to `vivarium-contract: v1`.

## The bug

[aubepkg/aube#1645](https://github.com/aubepkg/aube/pull/1645) —
pnpm-format lockfiles (`aube-lock.yaml`, `pnpm-lock.yaml`) record where
a `file:` directory or `link:` dependency lives, but no version. aube's
reader fills in a `0.0.0` placeholder, so everything that reads the
lockfile instead of resolving reports those packages as `0.0.0`:

```text
$ aube install                      # fresh resolve
+ filedep@1.0.0
+ linked@2.0.0
$ rm -rf node_modules && aube install --frozen-lockfile
+ filedep@0.0.0
+ linked@0.0.0
$ aube list
├── filedep 0.0.0
└── linked 0.0.0
```

The reproduction calls the reader directly — `aube_lockfile::parse_lockfile`
— on a project with one `file:` and one `link:` dependency, and compares
each package's version in the resulting graph with the one in its own
`package.json`:

```text
aube v2.6.1: parse_lockfile("app/")

package   specifier                 from lockfile   its package.json
filedep   file:./filedep            0.0.0           1.0.0   <- wrong
linked    link:../outside/linked    0.0.0           2.0.0   <- wrong
```

The upstream reference is a pull request rather than an issue: the bug
was reported together with its fix, so `1645` in the slug is the PR
number.

## Why this bug

- The bug lives entirely in the lockfile reader, which needs a
  filesystem to read but no network, processes, or links — so it runs
  in the browser rather than in a Layer 2 container.
- The verdict is a comparison of two strings per package, so the page
  emits a mechanically distinguishable `reproduced` / `unreproduced`.
- The fix is an open pull request. The fix-candidate pane runs its
  head, so the page shows the same fixture read by the latest release
  and by the fix, side by side. When the fix ships in a release, moving
  the baseline pin to that release flips the page to `unreproduced`.

## Why aube needs a patch at all

Every aube crate depends on aube-util, and aube-util depends on
`reqwest` and on tokio with its `full` feature set. On `wasm32-wasip1`,
tokio rejects `full` at compile time, `socket2` does not support the
target, and `reqwest`'s compression pulls in `zstd-sys`, a C library.
The lockfile reader uses none of them. The patch moves those
dependencies to `cfg(not(target_family = "wasm"))` and compiles out the
five aube-util modules that use them (`adaptive`, `fs`, `http`, `io`,
`snapshot`). Nothing in `aube-lockfile` or `aube-manifest` changes.

## Verdict contract — `vivarium-contract: v1`

The page conforms to the contract canonicalised in
[`../_shared/verdict.ts`](../_shared/verdict.ts). The `result` field
of the envelope reports `packages` (name, specifier, version from the
lockfile, version from `package.json`), `reproduced`, and `exit_code`,
plus the same fields for the fix-candidate build.

A `reproduced` verdict means **the bug reproduced** — at least one
local package's version in the lockfile graph differs from its
`package.json`, *and* the wasm exited 0. An `unreproduced` verdict
means the reader carries the real versions (exit 1), the wasm errored
before producing a result, or the WASI shim could not load.

## Native verification

Each crate also works as a normal Rust binary, writing the fixture to
the host's temp directory instead:

```bash
cd src/layer1_wasm/aube-1645
bash prepare.sh
cargo run --release
# verdict=reproduced — file: and link: deps read from the lockfile are 0.0.0

cargo run --release --manifest-path fix/Cargo.toml
# verdict=unreproduced — the lockfile graph carries the real versions (likely fixed upstream)
# exit code 1 — expected: this build is supposed to NOT reproduce
```

A native build compiles aube-util with its full dependency set, so it
takes several minutes; the wasm build is lighter.

## CI build of the wasm artefacts

`mise run repro:build:rust` runs every `src/layer1_wasm/*/prepare.sh`
before it scans for crates, and skips `.aube/` when it does, so the
fetched aube workspace is never built on its own. `mise run rust:check`
does the same before `cargo fmt --check` and `cargo clippy`.
